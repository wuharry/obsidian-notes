# TRPG 判定原則與參考

[測試索引](README.md)｜[bug 表](BUGS.md)｜[擲骰時機判準與對照證據](參考資料/擲骰時機與對照證據.md)

> 2026-09-07 整理。這是本產品採用的 DM 設計方向；不是把 D&D 規則整套移入現有自訂引擎。

| 面向 | 本產品原則 | 本場例子／驗收方式 |
|---|---|---|
| 玩家意圖 | 玩家描述想做什麼；AI 理解語意，引擎驗證 ID 與能力、提交結果 | 「告示」可依情境指公告欄，不要求技能名或精確物件名 |
| 擲骰時機 | 結果不確定且失敗有具體、有意義的後果才檢定；確定能做直接敘述，確定不能做說明阻礙 | 與老闆娘普通搭話不因酒館吵雜硬加 DC；說服拒絕通行的守衛則另論 |
| 澄清 | 先合併前文，缺資訊才問；補對象不能把已知目的清空 | 「我接著問」承接守衛，「去哪找鎮長」已提供目的 |
| 創意與結果 | 保留玩家合理的行動方法；修正保證成功的宣稱，不把行動改成任務導航 | 搭訕可被接受或拒絕，不能擅自轉成問任務 |
| 世界事實 | 可補符合設定的氣氛，不能憑空宣布可導航地點、地址或狀態改變 | 「大樓」一詞不必然違反奇幻；未設定的鎮長地址才是可查證缺口 |
| 主動鉤子 | DM 提供值得行動的理由與可選途徑；玩家仍可探索或拒絕 | 普通聊天不當成連續拒絕鉤子，更不能以轉場代替玩家選擇 |
| 線索備援 | 必要結論規劃至少三條線索作為設計檢查；不是每回合自動揭露三條 | 需另外盤點礦工事件每個必要結論的來源與失敗後路徑 |
| 操作可追溯 | 文字輸入與地圖點擊都應留下玩家行動及結果 | 點礦坑後應顯示「我透過地圖前往……」，再顯示抵達描述 |

> **擲骰時機的完整判準**（三條件、該擲／不該擲對照表、行動四分類白名單依據）與**逐條 bug 的正例／反例**
> 見 [擲骰時機與對照證據](參考資料/擲骰時機與對照證據.md)。本表只留結論，證據不在這裡重抄。

```text
DM 描述情境 → 玩家宣告行動（或點地圖）
→ 合併前文理解意圖 → 必要時只澄清缺少部分
→ 自動成立／有意義的檢定／說明實際阻礙
→ 引擎提交事實 → DM 保留原意敘述後果 → 留下對話紀錄
```

## 參考來源

- [D&D 2024 Basic Rules：Playing the Game](https://www.dndbeyond.com/sources/dnd/br-2024/playing-the-game)：官方說明描述情境、玩家宣告行動、DM 裁定的循環；不確定結果與有意義的失敗是能力檢定的重要判準。
- [Sly Flourish：Ability Check Toolbox](https://slyflourish.com/ability_check_toolbox.html)：討論如何讓隨機結果有意義，以及不需要時略過能力檢定。本產品據此避免用骰子阻擋普通互動。
- **Matt Colville《Running the Game》**（免費系列）：「玩家是被動反應的（reactive not proactive），DM 要主動給不去不行的鉤子」出自此；本產品據此要求 DM 給理由，但不因玩家探索或拒絕就收束。
- [The Alexandrian：Three Clue Rule](https://thealexandrian.net/wordpress/1118/roleplaying-games/three-clue-rule)：每個必要結論準備至少三條線索，降低漏掉單一線索造成停滯的風險。這是冒險設計建議，不是官方戰鬥規則。
- [使用者提供的跑團示例](參考資料/使用者提供的跑團示例.txt)：原文完整留存，僅作互動節奏的參考；不是 RUN-001，也未獨立核實節目集數與逐字稿來源。

## 不直接照搬的部分

- 「倒地補刀必定自動命中／處決」不是本次建立的通則；現有攻擊與失能規則仍由引擎處理。
- 「失敗讓故事有趣」用於設計後果，不要求 DM 保證每次失敗都愉快；也不能用反覆檢定讓關鍵資訊永久消失。
- 提示詞是模型行為指引，不能當成後端已保證零幻覺的證據。B004、B005、B007、B008 仍需真模型與真人複驗。
